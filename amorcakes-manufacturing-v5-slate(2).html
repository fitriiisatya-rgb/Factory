Upload PO Harian

Cukup upload CSV sheet tanggal (sheet "01", "02", dst) hasil download dari file PO — atau file .xlsx utuhnya, sheet tanggal akan dipilih otomatis. Dua bentuk layout dikenali otomatis:
• Karangtengah — header NO / KATEGORI / KODE / NAMA PRODUK, kolom TOTAL (PO Awal, PO Revisi, PB).
• Cibadak (Bolu) — header Kategori / Nama Produk / Harga Satuan, kolom TOTAL PO (PO Awal, PO Tambahan, PB); kode produk diambil dari katalog bawaan.
Jumlah kolom toko boleh berbeda tiap upload.
Ini baru pratinjau — data belum tersimpan. Cek dulu ringkasannya di bawah, lalu WAJIB klik tombol "Simpan sebagai Target Hari Ini" supaya benar-benar masuk ke sistem.

Riwayat Retur beban toko

Retur tidak memotong invoice dan tidak menyentuh produksi. Barangnya sudah jadi tanggung jawab toko sejak diterima. Data ditarik otomatis dari sheet Retur — tidak ada input manual di sini. Nilai Pabrik & Nilai Toko adalah angka referensi, bukan pengurang tagihan: Nilai Pabrik = harga yang ditagihkan ke toko, Nilai Toko = harga 100%/konsumen yang sedianya dijual toko ke pembeli. Rekonsiliasi lengkap (Dikirim = Terjual + Retur + Sisa Stok) ada di Dashboard → Arus Barang. Kalau barangnya rusak/cacat dari pabrik, itu masuk Reject, bukan di sini.

Reject dari Toko tanggungan produksi

Barang cacat/rusak dari pabrik (gosong, bau, berjamur, bentuk tidak standar). Ini tanggungan produksi, bukan beban toko. Dua tindak lanjut:
• Potong Invoice — tagihan toko dikurangi sebesar barang reject. Kerugian pabrik = nilai potongan.
• Ganti Barang Baru — tagihan tetap penuh, pabrik mengirim pengganti. Barang pengganti keluar gudang tanpa tambahan tagihan, jadi dicatat sebagai waste di Kartu Stok.
Wajib dipilih kalau ada baris bertindak lanjut "Potong Invoice".

Upload Penjualan POS (CSV)

Untuk laporan "Ringkasan berdasarkan Produk" dari POS — satu file berisi satu bulan penuh, semua toko, per produk per hari. Boleh diupload ulang kapan saja (harian, mingguan, atau di akhir bulan) — setiap upload dianggap paling benar untuk rentang tanggal & toko yang tercakup di file itu, jadi otomatis menggantikan data lama pada rentang yang sama (tidak dobel, dan koreksi/void ikut kebawa). Untuk pesanan non-outlet (Sales Eksekutif / CS / perorangan), pakai menu Pesanan — itu alur terpisah dan tidak tersentuh upload ini.
Data POS disimpan lokal di perangkat ini, tidak dikirim ke Google Sheets — satu bulan bisa puluhan ribu baris dan akan membuat sinkronisasi Sheets timeout. Kalau data hilang atau ganti perangkat, tinggal upload ulang file CSV-nya.

Cek Kecocokan Nama Produk (PO vs Master)

Kalau ejaan nama produk di PO beda dari Master Produk (mis. spasi ganda, singkatan, salah ketik), harga di Invoice tidak muncul karena pencocokan berbasis nama persis. Klik cek untuk mencari produk yang belum ada di Master, lengkap dengan tebakan nama yang mirip.

Omset Pabrik (Basedata)

Persentase omset pabrik yang sesungguhnya — flat, sama untuk semua tipe toko (Ownership maupun Franchise). Ini angka akuntansi/laporan sebenarnya, dipakai untuk metrik Omset Pabrik & Margin Kotor di Dashboard → Arus Barang. Beda dari persentase Invoice di bawah, yang dipakai backoffice untuk dokumen ke toko.

Rate Invoice / DO (Backoffice)

Keputusan bisnis final: rate Harga Invoice/DO flat 50% (Default Rate) untuk semua toko — Ownership maupun Franchise tidak lagi menentukan rate. Dipakai otomatis sbg isian awal Harga Satuan saat Invoice baru dibuat. Override 60% hanya tersedia per-dokumen saat reprint/edit invoice dengan permission yang benar (di layar Invoice, bukan di sini) — tidak pernah mengubah rate default toko atau dokumen historis lain.

Toko / Kanal

Tandai kanal tiap toko — Ownership/Franchise di sini murni metadata/pengelompokan laporan, tidak lagi memengaruhi rate Invoice/DO (selalu flat 50%, lihat kartu di atas).

Divisi tiap produk sudah diambil langsung dari kolom Divisi sheet DB (katalog bawaan), jadi tabel di bawah ini hanya dipakai kalau ada produk baru yang belum ada di katalog bawaan. Upload folder mobile/ (berisi produksi.html + ikon) ke tempat file ini di-hosting, lalu isi alamatnya di bawah — link yang dibagikan otomatis membawa URL Apps Script yang sama, tidak perlu diketik ulang di HP.

Baris Retur/Reject Tertahan

Tarik Data Retur & Reject

Menarik dari spreadsheet dbreturriject yang terpisah. Spreadsheet itu tidak perlu dipindahkan — cukup di-deploy sebagai Web App read-only, lalu tempel URL-nya di sini. Setiap baris dikenali lewat ID Transaksi, jadi menarik berulang kali tidak menggandakan data.
Retur masuk ke menu Retur (beban toko, tidak memotong tagihan). Reject masuk ke menu Reject sebagai tanggungan produksi dengan tindak lanjut di atas — bisa diubah per baris setelah masuk. Tindak lanjut "Potong Invoice" perlu invoice terkait, jadi kalau ditarik massal sebaiknya pilih "Ganti Barang Baru" lalu sesuaikan yang perlu dipotong.
